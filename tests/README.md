# Tests

Run the complete suite with `make test` or `python -m pytest`. The default run
includes every layer, including slow tests. No real TV, browser, display meter,
network service or GPU is required.

| Layer | Examples | What it protects |
| --- | --- | --- |
| Unit | `test_decode.py`, `test_backlight.py`, `test_colorimetry.py` | Transfer functions, filters, profile validation, physical units and state transitions. |
| Parity / golden | `test_memc_parity.py`, `test_oled_dynamics_parity.py`, `test_m14_parity.py`, `test_colorimetry_parity.py` | Independently saved pre-change rendered arrays, previews, profile identities, histories and artifacts. |
| End to end | `test_e2e.py`, `test_gallery.py`, `test_export_web.py`, CLI tests | Public rendering paths, command dispatch, reproducible artifact generation and complete manifests. |

Use `python -m pytest -m 'not slow'` for a shorter local run,
`python -m pytest -m golden` for saved-output checks, and
`python -m pytest -m e2e` for marked end-to-end modules. The `slow` marker
identifies costly galleries, exports, full temporal protocols and parity modules
with expensive setup. CI runs the whole suite.

Golden files in `fixtures/` are versioned evidence, not a cache. Their expected
values must not be generated by the same test execution being checked. Keep
changes to golden fixtures separate from runtime changes and explain their
source and expected effect in the pull request. Generated test artifacts use
pytest temporary directories; do not replace committed reports while testing.

Same-machine default-path off/on comparisons, repeated runs, checkpoint
continuation, discrete masks/reason codes, rational traces and profile YAML
bytes retain exact comparisons. For historical renders captured on another
machine, `golden_support.py` compares decoded values with these tolerances:

| Historical value | Tolerance |
| --- | --- |
| float32 rendered arrays/maps | `rtol=2e-6`, `atol=1e-7` |
| float64 rendered arrays/maps | `rtol=1e-12`, `atol=1e-12` |
| PNG / explicit uint8 previews | At most one code value per channel |
| CLI input PNGs | Exact decoded shape, dtype and pixels; encoded bytes may differ |
| FP16 web transport | At most one adjacent finite FP16 code |
| Finite floating values in historical JSON | `rtol=1e-12`, `atol=1e-12` |

Shapes, dtypes, archive member names and discrete values remain exact. PNG/NPZ
compression bytes are irrelevant to decoded-value comparisons. Nonfinite
rendered values fail. Web transport statistics use `rtol=1e-3`, `atol=1e-7`,
matching FP16 precision; its float32-to-FP16 maximum quantisation error uses
`atol=max(1e-7, peak_nits * 2e-6)` instead. JSON structure and nonfloating types,
rational timing strings, text, keys, counts and profile/text-source identities
remain exact. Float-bearing historical JSON is decoded regardless of filename;
its current byte length and SHA may differ due to roundoff or formatting. The
saved payload still authenticates against its original exact hash and length.
Rendered-value and encoded-image hashes are linked to decoded comparisons;
each current hash must first match its actual file bytes exactly. CLI source
paths are retained before basename normalisation so input files can be checked.
Input PNG pixels use exact equality, including rejection of a one-code change;
the preview tolerance never applies to these discrete inputs. OLED manifest
sample hashes authenticate raw RGB array bytes, not NPY container bytes, and
trial trace hashes authenticate their JSON files before decoded comparison.

The `rendered_reference_values.npz` fixture contains 1,100 references keyed by
the **unchanged historical SHA-256 values**. Raw array bytes or canonical
PNG/NPY/NPZ/FP16/JSON payload bytes must authenticate against that key before
decoding. References were recovered from outputs whose hashes matched the
existing captures; the original JSON baselines were not regenerated. Ordinary
digest equality is unchanged: tolerance requires an explicit historical
comparison. Focused helper tests cover accepted roundoff, rejected drift,
authentication, dtype/shape changes, discrete codes and linked hashes.

CPython 3.12 changed float `sum` accuracy; eight aggregated M14 luminance MAEs
differ by one float64 step on Python 3.11 even with NumPy held fixed. M19b extends
decoded comparison to all historical JSON, including PTS/capacity traces and
motion CLI diagnostics. Float-to-integer substitutions and nonfinite numbers
fail. Nested PTS trace array hashes resolve from the experiment root and must
authenticate their current array bytes before decoded comparison. The existing
gallery `memc_trace.json` hash stays strict: its only floats are deterministic
0/1 fallback fractions and rational-to-float frame durations. Historical M13
checkpoint environment identities accept the current NumPy version after checking it
equals `numpy.__version__`; checkpoint checksums and all remaining state fields
are still validated. Runtime checkpoint compatibility checks are unchanged.

The existing numerical validation JSON/CSV comparisons retain their `2e-6`
relative / `1e-7` absolute tolerance. These captures were saved from the
unmodified M15 implementation during M16 and authenticate against the existing
pre-M7 JSON/CSV hashes. Full gallery metadata comes from the committed pre-M13
capture, authenticated against the pre-M9 manifest hash.

`golden_support.py` also restores a small, explicit set of historical package
and documentation labels before comparing migrated metadata. These compatibility rules
allow the source layout and documentation paths to change without rewriting
the historical golden evidence.
